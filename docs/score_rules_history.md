# SpotDiffs 得分规则变更历史

本文记录 `/game/[slug]` 找不同游戏的旧版得分规则，以及 2026-08-26 上线的 Performance V1 得分与排行榜计分规则。XP 是独立的长期成长系统，当前项目尚未实现 XP 累计，因此本文只记录竞技得分（Score）和排行榜总分。

## 版本概览

| 版本 | 使用时间 | 单局分数范围 | 全局排行榜累计方式 |
| --- | --- | ---: | --- |
| V0 原始规则 | 2026-08-26 以前 | 随关卡差异数量变化；当前本地关卡最高 2,000 分 | 每次通关都把整局分数累加到用户总分 |
| V1 Performance | 2026-08-26 起 | 最高 3,000 分 | 每关只贡献个人最佳分（PB），刷新 PB 时只增加差值 |
| V1.1 关卡首次成绩榜 | 2026-08-27 起 | 沿用 V1，最高 3,000 分 | `/game/[slug]` Statistics 只按每位用户的首次完成成绩排名 |

## V0：原始得分规则

### 最终得分公式

```text
Final Score =
  1000
  + max(0, 300 - timeElapsed)
  + floor(found / totalClicks × 500)
  + maxComboBeforeFinalClick × 50
  - hintsUsed × 100

Final Score = max(0, Final Score)
```

各部分含义：

| 项目 | 规则 | 最高值 |
| --- | --- | ---: |
| 基础分 | 完成关卡固定获得 | 1,000 |
| 时间奖励 | `max(0, 300 - 完成秒数)` | 300 |
| 准确率奖励 | `floor(找到数 / 总点击数 × 500)` | 500 |
| Combo 奖励 | 完成瞬间代码中已有的 `maxCombo × 50` | 随差异数量变化 |
| Hint 惩罚 | 每使用一次提示扣 100 分 | 无奖励上限 |

误点不会被单独扣固定分，但会增加 `totalClicks`、降低准确率奖励，并中断 Combo。

游戏过程中的 `+200`、`+250` 等浮动提示只用于点击反馈，并不会逐项累加到最终得分。

### 原规则最多能得多少分

要取得最大值，需要：

- 在计时器第一次递增前完成，使 `timeElapsed = 0`；
- 全程无误点，准确率为 100%；
- 不使用提示；
- 连续找出所有差异。

设关卡共有 `N` 个差异。旧代码在最后一次成功点击中先异步更新 Combo，但计算最终分数时仍读取更新前的 `maxCombo`，所以实际参与结算的最大 Combo 是 `N - 1`。

```text
旧版实际最高分 = 1000 + 300 + 500 + (N - 1) × 50
                 = 1800 + (N - 1) × 50
```

旧规则没有全局固定上限，因为关卡差异数量 `N` 可以继续增加。仓库 `data/levels.ts` 中现有本地关卡最多有 5 个差异，因此该数据集下的实际最高分为：

```text
1800 + (5 - 1) × 50 = 2,000 分
```

如果旧代码把最后一次点击形成的 Combo 也正确计入，5 个差异时本应为 2,050 分；但历史实现的实际结果是 2,000 分。

### V0 排行榜问题

每次插入一条 `game_records` 记录后，数据库都会执行：

```text
profiles.total_score += 本局完整 score
```

因此同一个关卡可以无限重玩，即使没有刷新个人最佳，也会持续提高全局排行榜总分。单关排行榜虽然使用最高分，但全局排行榜使用累计总分，两者口径不一致。

## V1：Performance 得分规则

V1 将一局表现拆成速度、准确率、提示依赖和完成度四个标准化维度，每个维度范围均为 0～100。

### Target Time

目标时间优先使用关卡明确配置的 `levels.target_time`。没有配置时，根据难度和差异数量 `N` 自动生成，并四舍五入到最接近的 5 秒：

| 难度 | Target Time 公式 |
| --- | --- |
| Easy | `20 + N × 12` |
| Medium | `22 + N × 15` |
| Hard | `25 + N × 18` |
| Expert | `30 + N × 24` |

`average_time` 只保留为统计指标，不再直接参与实时竞技评分，避免目标时间被挂机、异常值或重复游玩持续改变。

### T：速度分（40%）

T 使用以下锚点做分段线性插值：

| 完成时间 | T |
| ---: | ---: |
| `≤ 0.5 × target` | 100 |
| `0.75 × target` | 90 |
| `1.0 × target` | 75 |
| `1.5 × target` | 50 |
| `≥ 2.0 × target` | 0 |

因此，在 Target Time 内完成代表速度表现良好（T=75），只有明显快于目标时间的玩家才能取得 90～100 的速度分。

### A：准确率分（30%）

```text
accuracy = found / totalClicks × 100%
```

| Accuracy | A |
| ---: | ---: |
| 100% | 100 |
| 98%～不足 100% | 95 |
| 95%～不足 98% | 90 |
| 90%～不足 95% | 80 |
| 80%～不足 90% | 60 |
| 70%～不足 80% | 40 |
| 不足 70% | 20 |

### H：提示依赖分（20%）

| Hint 次数 | H |
| ---: | ---: |
| 0 | 100 |
| 1 | 90 |
| 2 | 80 |
| 3 | 60 |
| 4 | 40 |
| 5 次及以上 | 20 |

### C：完成度分（10%）

| 完成度 | C |
| ---: | ---: |
| 100% | 100 |
| 80%～不足 100% | 70 |
| 60%～不足 80% | 40 |
| 不足 60% | 0 |

`/game/[slug]` 仅在找完全部差异后结算，所以正常完成局的 C 为 100。

### Performance 与最终分数

```text
P = round(0.4T + 0.3A + 0.2H + 0.1C)
Final Score = P × 30
```

因此：

- `P` 是 0～100 的整数；
- 最高分为 3,000 分，与历史数据库中约 3,000 分的单关最高水平保持接近；
- 由于 A、H 的最低维度分均为 20，计算函数的实际最低分为 300；正常完成全部差异时 C=100，实际最低分为 600；
- 当前最终得分以 30 分为步长；
- Performance 和 Rating 不受缩放系数影响。

满分条件为 T、A、H、C 全部达到 100，即在不超过 `0.5 × targetTime` 的时间内完成、无误点、不使用提示并完成全部差异。

### Rating 评级与硬门槛

先按 Performance 给出建议评级：

| Performance | 建议 Rating |
| ---: | --- |
| 95～100 | S+ |
| 90～94 | S |
| 80～89 | A |
| 70～79 | B |
| 不足 70 | C |

再应用硬门槛，不满足时只能向下降级：

| Rating | 必须满足 |
| --- | --- |
| S+ | 100% 完成、0 Hint、Accuracy ≥ 98%、T ≥ 90 |
| S | 100% 完成、Hint ≤ 1、Accuracy ≥ 95% |
| A | 100% 完成 |
| B | 完成度 ≥ 80% |
| C | 其余情况 |

Rating 用于结果展示和未来 XP 换算，不会在当前版本额外乘算 Score。

## V1：排行榜防重复刷分规则

全局排行榜总分改为：

```text
Global Total Score = Σ 每个不同关卡的个人最佳分
```

每局实际贡献为：

```text
scoreContribution = max(本局分数 - 该关历史 PB, 0)
```

| 场景 | 排行榜变化 |
| --- | ---: |
| 首次完成某关 | 增加本局全部分数 |
| 重玩且低于或等于 PB | +0 |
| 重玩并刷新 PB | 只增加新旧 PB 的差值 |

游戏记录仍按每次尝试保存，重玩自由不受限制；只有排行榜贡献被限制。原有 `level_leaderboard` 数据视图继续保留每位玩家的最高分口径，供兼容现有功能使用。

数据库还执行以下保护：

- 在写入前重新计算 Performance、Rating 和最终分数；
- 对不存在的关卡 slug 拒绝写入；
- 游戏记录对普通用户保持只追加，禁止通过删除旧 PB 后重新领取贡献分；
- 迁移时将历史 `profiles.total_score` 重算为各关 PB 之和，修复旧规则造成的虚高总分。

## V1.1：Statistics 首次参与排行榜

`/game/[slug]` 的 Statistics Tab 使用独立的首次参与榜，不再展示个人最佳分榜。每位登录用户只有第一次完整通关并成功写入数据库的成绩参与该关排名；游客记录和后续重玩记录不参与。

```text
First Attempt = 每个 user_id + level_slug 按完成时间最早的一条记录
```

排名依次比较：分数更高、耗时更短、准确率更高、首次完成时间更早，最后用用户 ID 保证顺序稳定。榜单只展示前 10 名，但榜外登录用户仍可看到自己的真实名次。

数据库通过 `is_first_attempt` 标记、用户级事务锁和唯一部分索引保证每位用户每关最多只有一条首次记录。客户端传入的标记会被写入触发器覆盖，因此伪造时间、重复提交或刷更高分都不能改变首次成绩榜。历史记录迁移时按 `played_at`、`created_at` 和记录 ID 回填最早一次。

该规则只影响关卡详情 Statistics 榜单，不改变 V1 全局排行榜按每关 PB 累计的规则。
