对于 **SpotDiffs** 这种网页休闲游戏，我更建议把 **Score（本局得分）** 和 **XP（成长经验）** 分开，因为它们服务于完全不同的目标。

***

# 第一性原理

一个游戏其实有两条完全独立的成长线：

```
本局表现（Session）
        │
        ▼
      Score

```

和

```
长期成长（Lifetime）
        │
        ▼
        XP

```

它们回答的问题不同。

| 系统    | 回答的问题        |
| :---- | :----------- |
| Score | 这一局玩得怎么样？    |
| XP    | 我长期成长到了什么程度？ |

***

# 我的建议（按 SpotDiffs 的定位）

如果 SpotDiffs 的目标是成为一个**长期运营的品牌网站**，而不是单纯的小游戏集合，我建议保留两套系统，但各司其职：

<br />

| 系统        | 是否保留 | 用途                               |
| :-------- | :--- | :------------------------------- |
| **Score** | ✅ 保留 | 用于排行榜、个人最佳（PB）、每日挑战和分享，体现这一局的表现。 |
| **XP**    | ✅ 保留 | 用于等级、称号、徽章和长期成长，体现玩家积累。          |

两者之间通过\*\*评级（Rating）\*\*建立联系，而不是直接相等。例如：

```
Final Score: 8,920
        │
        ▼
🏆 S Rank
        │
        ▼
+180 XP
        │
        ▼
Level 19 (78%)

```

这种设计有几个好处：

- **Score** 可以针对每一关重新竞争，不会因为历史积累失去意义。
- **XP** 可以保持稳定增长，不会因为某一局发挥特别好而打乱成长节奏。
- **S Rank / Perfect** 成为用户愿意截图分享的核心内容，而 XP 和等级则驱动长期留存。

**如果必须在两者之间二选一**，我会选择保留 **XP** 而不是 **Score**；但如果希望 SpotDiffs 有排行榜、每日挑战和竞速玩法，那么**同时保留 Score 和 XP** 会是更完整、更有扩展性的设计。

### SpotDiffs Performance（表现）系统 V1 规范

目标：用一套稳定、可运营、可扩展的算法，把玩家一局游戏的表现量化为 0\~100 的 Performance Score，再用于 S+/S/A/B/C Rating、XP 奖励 和 排行榜展示。

### 最终推荐：4 个维度 + 1 个总公式

| 维度              | 权重  | 衡量什么         |
| :-------------- | :-- | :----------- |
| Time（速度）        | 40% | 是否比该关的目标时间更快 |
| Accuracy（准确率）   | 30% | 是否少误点、精准找到差异 |
| Hint（提示依赖）      | 20% | 是否依赖提示完成     |
| Completion（完成度） | 10% | 是否完整通关       |

核心公式

### Performance Score

### P = 0.4T + 0.3A + 0.2H + 0.1C

其中 T/A/H/C 都是 0\~100 的标准化分数。

### 一、各维度的计算标准

### 1. Time（速度）T

每个关卡都配置一个 Target Time（目标时间），例如 40 秒。

| 玩家耗时 t             | T 分数 |
| :----------------- | :--- |
| t ≤ 0.5 × target   | 100  |
| 0.5\~0.75 × target | 90   |
| 0.75\~1.0 × target | 75   |
| 1.0\~1.5 × target  | 50   |
| 1.5\~2.0 × target  | 25   |
| 2.0 × target       | 0    |

推荐实现（线性版）

更平滑，适合代码实现

### T = clamp(100 × (2 - t/target), 0, 100)

其中 clamp(x,0,100) 表示限制在 0\~100 之间。

目标时间

40 秒

20 秒

T=100

顶级速度

30 秒

T=90

很快

40 秒

T=75

达标

60 秒

T=50

偏慢

80 秒

T=0

超时

### 2. Accuracy（准确率）A

定义：

### Accuracy = found / totalClicks

found = 找到的差异数；totalClicks = 所有点击次数（包含误点）。

| 准确率     | A 分数 |
| :------ | :--- |
| 100%    | 100  |
| 98\~99% | 95   |
| 95\~97% | 90   |
| 90\~94% | 80   |
| 80\~89% | 60   |
| 70\~79% | 40   |
| < 70%   | 20   |

示例

10 个差异

10 次点击找到 10 个

100%

A=100

11 次点击找到 10 个

91%

A=80

15 次点击找到 10 个

67%

A=20

### 3. Hint（提示依赖）H

| Hint 次数 | H 分数 |
| :------ | :--- |
| 0       | 100  |
| 1       | 90   |
| 2       | 80   |
| 3       | 60   |
| 4       | 40   |
| ≥5      | 20   |

Perfect 条件之一

Hint = 0 是获得 S+ 的必要条件。

### 4. Completion（完成度）C

| 完成比例    | C 分数 |
| :------ | :--- |
| 100%    | 100  |
| 80\~99% | 70   |
| 60\~79% | 40   |
| < 60%   | 0    |

硬规则

未 100% 完成时，最高只能获得 B。

### 二、总公式（可直接实现）

最终公式

### Performance Score

### P = 0.4T + 0.3A + 0.2H + 0.1C

| 维度         | 分数  | 权重  | 贡献   |
| :--------- | :-- | :-- | :--- |
| Time       | 95  | 0.4 | 38.0 |
| Accuracy   | 90  | 0.3 | 27.0 |
| Hint       | 100 | 0.2 | 20.0 |
| Completion | 100 | 0.1 | 10.0 |
| 合计         | —   | —   | 95.0 |

结果

### P = 95 → Rating = S+

随后再通过硬性门槛校验是否真的允许 S+。

### 三、硬性门槛（Hard Gates）

Performance 分数只是“建议等级”，最终还要经过硬性门槛过滤。

| 等级 | 必须满足                               |
| :- | :--------------------------------- |
| S+ | 100% 完成、0 Hint、准确率 ≥ 98%、Time ≥ 90 |
| S  | 100% 完成、Hint ≤ 1、准确率 ≥ 95%         |
| A  | 100% 完成                            |
| B  | 完成度 ≥ 80%                          |
| C  | 其余情况                               |

### 关键限制

即使 P=99，只要用了 2 次 Hint，也不能拿 S，只能降到 A。

### 四、Rating 判定流程

1. 计算 T/A/H/C

   得到四个 0\~100 分。
2. 计算 P

   P = 0.4T + 0.3A + 0.2H + 0.1C
3. 按分数给“建议等级”
   | P 区间    | 建议等级 |
   | :------ | :--- |
   | 95\~100 | S+   |
   | 90\~94  | S    |
   | 80\~89  | A    |
   | 70\~79  | B    |
   | < 70    | C    |
4. 应用硬性门槛

   不满足条件就降级，直到满足为止。

### 五、代码伪实现（TypeScript）

上线建议

先把 Target Time 写死在关卡配置里，不要一开始就做动态统计。等积累 1 万局以上数据后，再把 targetTime 改成“该关中位完成时间 × 0.85”。这样 S 评级的稀有度会自动稳定在约 5%\~10%。

### 最终你需要落库的字段（最小集合）

复制清单

| 字段            | 类型              |
| :------------ | :-------------- |
| time          | number          |
| targetTime    | number          |
| found         | number          |
| totalClicks   | number          |
| hints         | number          |
| completion    | number (0\~1)   |
| T / A / H / C | number (0\~100) |
| performance   | number (0\~100) |
| rating        | S+/S/A/B/C      |

一句话总结： 先把玩家表现压缩成 0\~100 的 Performance Score，再用硬性门槛得到 S+/S/A/B/C，最后由 Rating → XP 驱动长期成长。这套结构最稳定，也最容易迭代。

# Performance Rating 对应 XP 的计算方式

***

## 我推荐的方案：Base XP + Performance Bonus

不要让 XP 完全由 Rating 决定。

而是：

```text
XP
=
Base XP（由 Rating 决定）
+
Performance Bonus（由 Performance 决定）
+
Achievement Bonus（由成就决定）
```

这样成长会自然很多。

***

### 第一步：Rating 决定 Base XP

例如：

| Rating | Base XP | 设计目的     |
| :----- | ------: | :------- |
| S+     |     180 | 顶级表现     |
| S      |     150 | 优秀       |
| A      |     120 | 良好       |
| B      |      90 | 合格       |
| C      |      60 | 完成即可获得成长 |

注意：

**Base XP 的差距不要太大。**

否则高手升级会越来越快，新玩家很容易放弃。

我建议：

> 每个等级之间保持 **20\~30 XP** 的差距即可。

***

### 第二步：Performance Bonus

Performance 已经计算出来了（0\~100）。

可以转换成：

| Performance | Bonus XP |
| :---------- | -------: |
| 95\~100     |      +30 |
| 90\~94      |      +20 |
| 85\~89      |      +15 |
| 80\~84      |      +10 |
| 70\~79      |       +5 |
| <70         |        0 |

例如：

玩家：

```text
Performance = 97

Rating = S+
```

得到：

```text
Base XP

180
```

- <br />

```text
Performance Bonus

30
```

\=

```text
210 XP
```

另一位玩家：

```text
Performance = 91

Rating = S
```

得到：

```text
150

+

20

=

170 XP
```

虽然都是优秀玩家，

但是表现越好，

XP 越高。

***

### 第三步：Achievement Bonus（最重要）

这一层才是真正驱动玩家行为的。

例如：

| Achievement        |  XP |
| :----------------- | --: |
| No Hint            | +20 |
| 100% Accuracy      | +15 |
| New Personal Best  | +20 |
| Daily Challenge    | +30 |
| First Win Today    | +10 |
| 7-Day Streak       | +15 |
| New Badge Unlocked | +20 |

例如：

这一局：

```text
Rating

S
```

↓

```text
Base XP

150
```

↓

```text
Performance Bonus

20
```

↓

```text
No Hint

20
```

↓

```text
New PB

20
```

↓

```text

15
```

\=

```text

```

这样玩家看到的不只是：

> 我拿了 150 XP。

而是：

> 我今天拿了 225 XP，因为我没有用 Hint，还刷新了纪录。

这会强化他们对优秀行为的追求。

# 我还建议增加一个「关卡难度系数（Difficulty Multiplier）」

对于 SpotDiffs，不同关卡的难度可能差异很大。如果一张图只有 5 个差异，另一张图有 20 个差异、背景复杂，它们给相同 XP 就不太合理。

因此我建议最终公式再加一个难度系数：

```text
Total XP =
(
Base XP
+ Performance Bonus
+ Achievement Bonus
)
× Difficulty Multiplier
```

例如：

| 难度     |   系数 |
| :----- | ---: |
| Easy   | ×1.0 |
| Medium | ×1.1 |
| Hard   | ×1.2 |
| Expert | ×1.4 |

这样即使都是 **S Rating**：

- Easy 关卡：150 XP
- Hard 关卡：188 XP
- Expert 关卡：225 XP

玩家也会更愿意挑战高难度内容，同时整个成长体系仍然保持清晰、可控且易于运营。
